# Как интерактив встроен в обучение

Интерактив — часть объяснения в уроке. Он расположен после основных понятий и разобранного примера, перед самостоятельной практикой и тестом. Последовательность: **предположить → изменить условие → увидеть результат → объяснить его словами**. Модуль не заменяет чтение и не служит обязательным игровым барьером.

Тексты и ситуации самостоятельные. Учебные примеры не воспроизводят задания Harvard/edX. Наличие интерактива не означает, что сайт проводит официальный курс или выставляет оценку от университета.

## Восемь моделей

| Тип | Что делает учащийся | Что становится видно | Ограничение |
| --- | --- | --- | --- |
| `argument-map` | Включает основания, скрытое допущение и возражение к двухнедельному пилоту тихих часов. | Почему опыт другого отдела недостаточен без переноса условий; почему вывод остаётся вероятностным. | Проверяется структура заданного примера. Система не устанавливает истинность посылок и не анализирует произвольный аргумент. |
| `bayes` | Меняет долю спама, обнаружение спама и частоту ложных тревог. | Вероятность после сигнала, абсолютные числа в выборке 10 000 и доля ложных сигналов. | Все числа задаются пользователем, это не статистика почтовой системы. |
| `fallacy` | Разбирает пять ситуаций, включая корректное рассуждение. | Конкретный разрыв между посылкой и выводом, способ его исправления. | Название ошибки не заменяет её обоснование; несогласие само по себе не ошибка. |
| `rhetoric` | Собирает речь из вариантов этоса, логоса и пафоса, пишет заключение. | Как меняется доверие, проверяемость и эмоциональное давление. | Правила разбора относятся к готовым блокам. Свободный текст не получает фиктивную «AI-оценку». |
| `framing` | Меняет результат и формулировку, отмечает первую реакцию. | Два взаимодополняющих описания одного набора данных. | Смена рамки сама по себе не ложь. Реакция пользователя не оценивается как правильная или неправильная. |
| `justice` | Распределяет фиксированные 100 единиц и переключает принципы оценки. | Разница между равенством ресурсов, суммой условной полезности и минимальной долей. | Полезность вымышлена; ни один показатель не объявлен общей мерой справедливости. |
| `veil` | Выбирает распределение, затем раскрывает свою случайную позицию. | Отличие выбора правила от выбора в собственных интересах; равенство и высокий минимум могут расходиться. | Лотерея — иллюстрация, не полное изложение исходной позиции Ролза. |
| `market` | Меняет условия торговли, сравнивает аргументы и фиксирует позицию. | Отличие вопросов пользы, добровольности, неравенства и смысла блага. | Детерминированные пояснения не прогнозируют реальное поведение; моральная позиция не получает автоматического балла. |

Модели подходят к нескольким урокам. Поля `prompt` и `reflection` связывают одинаковый эксперимент с разными учебными вопросами. Если для новой темы нужен иной набор фактов, добавляется новый тип или явно версионируемая конфигурация; менять утверждения в заголовке без изменения модели нельзя.

## Приоритет телефона

- Вертикальные схемы, адаптивные блоки; основной сценарий не требует горизонтального перемещения.
- Сенсорное управление и обычная клавиатура. Drag-and-drop не используется.
- Кнопки и основные контролы высотой не менее 44 CSS px.
- Числовые параметры доступны через ползунок и числовое поле. Допустимое число пересчитывает результат сразу по `input`; редактируемое поле при этом не перезаписывается, сохраняя позицию ввода. Пустое, частично набранное или выходящее за диапазон значение остаётся черновиком до `change`, после чего восстанавливается или ограничивается допустимым целым значением.
- В учебных моделях нет зависящих от hover подсказок. Пояснения раскрываются стандартным `details/summary`.
- Все значимые значения продублированы текстом. Цвет не служит единственным носителем смысла.
- `aria-pressed`, текстовые подписи, областное объявление результатов, видимый фокус, учёт `prefers-reduced-motion`.
- Поля свободного текста имеют размер шрифта 16 px и ограничение длины. Внешних запросов, сторонних шрифтов или сервисов внутри интерактивов нет.

## Подключение

```js
import { mountInteractive } from './src/interactives/index.js';

const dispose = mountInteractive(container, lesson.interactive, {
  savedState: progress.interactives[lesson.id] ?? {},
  onSave(nextState) {
    progress.interactives[lesson.id] = nextState;
    persist(progress);
  },
});

// При смене урока:
dispose();
```

Файл `index.js` сам импортирует `interactives.css`. Его можно загружать динамическим `import()` при открытии урока. `mountInteractive` синхронно создаёт HTML и возвращает функцию снятия обработчиков событий. Экземпляры не используют глобальные DOM-селекторы, а заголовки имеют уникальные идентификаторы.

Конфигурация урока:

```js
{
  type: 'bayes',
  title: 'Почему точный фильтр может часто ошибаться?',
  prompt: 'Сначала предположите ответ. Затем сравните частый и редкий спам.',
  reflection: 'Почему одного процента обнаружения недостаточно для оценки сигнала?'
}
```

Если урок уже выводит заголовок, приглашение к эксперименту и вопрос для размышления, передайте `embedded: true` в конфигурации. Тогда виджет выводит только тело эксперимента и получает доступное имя через `aria-label`. В самостоятельной лаборатории это поле можно не передавать: заголовок и раскрываемая рефлексия остаются внутри модуля.

Сохранённое состояние считается недоверенным: числовые значения ограничиваются диапазонами, строки — длиной, списки — допустимыми вариантами. Текст экранируется перед включением в HTML. При смене сценария рынка прежняя позиция и объяснение очищаются, поскольку относились к другому вопросу. Остальные условия сохраняются для сравнения.

Сохранение реализует вызывающая сторона. Приложение должно предупреждать об ошибке постоянного хранилища и не обещать синхронизацию между устройствами без сервера.

## Вычисления

Байес: `TP = N × P(spam) × sensitivity`, `FP = N × (1 − P(spam)) × falsePositiveRate`, `P(spam | signal) = TP / (TP + FP)`. Отсутствие сигналов даёт неопределённую условную вероятность; вычислительная функция возвращает `null`.

Распределение: изменение одной доли сохраняет сумму 100; оставшаяся сумма делится между двумя людьми пропорционально их предыдущим долям, с целочисленным округлением. Если обе доли были нулевыми, остаток делится почти поровну. Это правило интерфейса, а не моральный принцип.

Условная полезность: `Σ cᵢ × √xᵢ`. Наборы коэффициентов — `[1, 1, 1]` и `[1, 1.5, 2]`. Кнопка максимума перебирает 5 151 допустимое распределение целых единиц. Оптимум зависит от выбранной функции и не является универсально справедливым распределением.

`tests/interactives.test.js` проверяет расчёт условной вероятности, граничные случаи, сохранение 100 единиц при крайних/повреждённых входных данных и различие принципов при смене коэффициентов. Проверку макета и взаимодействий в браузере следует проводить отдельно на ширинах 320, 390 и 768 px.
